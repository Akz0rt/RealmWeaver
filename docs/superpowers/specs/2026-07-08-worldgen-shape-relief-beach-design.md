# Генерация: изрезанный материк, усиленный рельеф, прибрежный пляж — Design Spec

**Дата:** 2026-07-08
**Ветка:** `map-terrain-raster`
**Место в дорожной карте:** Подпроект **A (Генерация)** из декомпозиции «тёмный фэнтези-рендер карты» на
A (генерация) → B (векторный рендер регионов) → C (декорации: иконки/подписи/рамка). Этот spec покрывает
только A. B и C — отдельные spec'и.

## Контекст и цель

Текущий GPU-рендер уже даёт органичные границы, свечение берега и плоскую заливку, но карта не читается как
макет `design_handoff_realmweaver_map` (Terra Umbrarum) по трём причинам, и все три — **на стороне генерации**,
а не рендера:

1. **Форма материка квадратная** и заполняет почти весь квадрат карты (узкая прямая кромка воды).
2. **Рельеф вялый** — разброс высот на клетках слишком мал, hillshade почти плоский.
3. **Пляж непредсказуем** — прибрежного песчаного канта либо нет, либо он рваный.

Цель подпроекта A — переработать вход генерации так, чтобы получался **крупный изрезанный материк в
бескрайнем океане**, с **выразительным рельефом** и **гарантированным тонким песчаным поясом по берегу** —
то есть подготовить «правильные данные», под которые дальше (подпроект B) пишется векторный рендер.

Все три изменения — тюнинг существующего Patel-style пайплайна (`WorldGenerator`), без смены модели данных
клетки. Старые `.dndproj` сейвы не ломаются: они хранят уже сгенерированные клетки, а не перегенерируют их
(подтвердить на этапе плана — см. «Обратная совместимость»).

## Общие ограничения

- Слой генерации (`Assets/WorldGen/Generation/`) остаётся чистым C# без зависимости от `UnityEngine`.
- Всё новое поведение — через `GenerationParams` с дефолтами; сид управляет вариативностью. Существующий
  паттерн проекта (все ручки уже вынесены в `GenerationParams`).
- Модель данных клетки (`VoronoiCell`: `Height`, `Biome`, `IsOcean`, `NeighborIds`, override-поля) **не меняется** —
  меняется только логика, которая её заполняет.
- Изменения вносятся в **оба** пути генерации: `WorldGenerator.GenerateWorld` и `GenerateWorldStepped`
  (прогресс-экран). Они должны остаться поведенчески эквивалентны.
- Self-тесты по конвенции проекта (маленькая фикстура + PASS/FAIL), на чистых классах генерации.

## A1. Форма мира — изрезанный материк в бескрайнем океане

### Корень проблемы

`HeightmapGenerator.ComputeFalloff` (файл `HeightmapGenerator.cs:78-89`):

```csharp
float d = MathF.Max(MathF.Abs(nx), MathF.Abs(ny)); // Chebyshev → квадрат
if (d < innerRadius) return 0f;                     // innerRadius=0.5 → огромное плато
float adjusted = (d - innerRadius) / (1f - innerRadius);
return MathF.Pow(adjusted, falloffPower);            // falloffPower=2.5 → узкая резкая кромка
```

Квадратная метрика + большое центральное плато + резкая кромка = материк-квадрат, заполняющий карту, с
прямой узкой полосой воды. Доменно-искажённый базовый шум почти не успевает «изрезать» берег, потому что зона
перехода к морю слишком тонкая.

### Изменение — «искажённый радиальный falloff»

Переписать `ComputeFalloff` (и конструктор `HeightmapGenerator` для новых параметров):

1. **Радиальная (евклидова) метрика** вместо Chebyshev: `d = hypot(nx', ny')`, где `nx', ny'` — координаты
   относительно (возможно смещённого) центра материка. Даёт округлую основу и гарантированный океан в углах
   карты (в углах `d ≈ 1.41 > 1` → falloff насыщается в 1 → глубокая вода).
2. **Меньше плато, шире переход:** дефолты `InnerRadius: 0.5 → 0.2`, `FalloffPower: 2.5 → 1.8`. Центральное
   «сухое» ядро уменьшается, зона берегового перехода расширяется — именно в ней шум лепит полуострова, бухты,
   прибрежные островки.
3. **Береговой шум:** отдельный низкочастотный fbm (`FastNoiseLite`, свой seed-сдвиг) добавляется к `d` перед
   порогом: `d += (coastNoise(x,y) - 0.5f) * CoastRoughness`. Гуляющий по кругу радиус берега → фьорды и мысы
   вместо гладкого овала.
4. **Вариативность по сидам:**
   - **Джиттер центра материка** — центр `(cx, cy)` в нормированном пространстве `[-1,1]` смещается на
     детерминированную по сиду величину в пределах `±ContinentCenterJitter` (дефолт 0.18). Материк перестаёт
     всегда сидеть ровно в центре карты.
   - Базовый шум и warp уже варьируются сидом; вместе с джиттером центра и береговым шумом это даёт заметно
     разные силуэты для разных сидов.
5. **Материк остаётся крупным**, но по всему периметру гарантирован океан: при `d ≥ 1` (середина ребра карты)
   `adjusted ≥ 1` → falloff = 1 → вода. Джиттер центра ограничен (`≤ 0.2`), чтобы материк не «уехал» в край.

Итоговая форма `ComputeFalloff`:

```csharp
float nx = 2f*(x/mapWidth) - 1f - centerOffsetX;   // centerOffsetX/Y детерминированы по сиду
float ny = 2f*(y/mapHeight) - 1f - centerOffsetY;
float d  = MathF.Sqrt(nx*nx + ny*ny);
d += (coastNoise.GetNoise(x, y) * 0.5f) * coastRoughness; // GetNoise∈[-1,1] → вклад ±0.5·rough
if (d < innerRadius) return 0f;
float adjusted = (d - innerRadius) / (1f - innerRadius);
return MathF.Pow(Math.Clamp(adjusted, 0f, 1f), falloffPower);
```

### Новые/изменённые параметры (`GenerationParams`)

| Параметр | Старый дефолт | Новый дефолт | Роль |
|---|---|---|---|
| `InnerRadius` | 0.5 | **0.2** | размер центрального плато (меньше = раньше начинается берег) |
| `FalloffPower` | 2.5 | **1.8** | резкость спада (меньше = шире рваная кромка) |
| `CoastRoughness` *(new)* | — | **0.2** | амплитуда бергового шума (изрезанность) |
| `CoastRoughnessFrequency` *(new)* | — | **0.004** | частота берегового шума (крупные мысы vs мелкая рябь) |
| `ContinentCenterJitter` *(new)* | — | **0.18** | разброс центра материка по сидам |

`SeaLevel` (0.35) и `WarpAmplitude` (40) остаются. Метрика (радиальная) — это код, не параметр (сознательно без
toggle, чтобы не тащить мёртвую квадратную ветку; см. Риски).

### Companion (render-side, НЕ генерация)

Чтобы иллюзия «суша в бескрайнем море» работала, **фон редактора карты = цвет глубокого океана** (цвет очистки
камеры карты либо океан-плоскость/бэкдроп под квадом), тогда вода на краю текстуры бесшовно перетекает в фон.
Это единственный render-touch подпроекта A: маленькая правка сцены/камеры, выполняется вместе с A, но помечена
как render-side. Точный цвет берётся из палитры (тот же «глубокий океан», что рисует шейдер у дальней воды),
финальная состыковка тона фон↔дальняя вода уточняется в подпроекте B.

## A2. Рельеф — умеренно сильнее

### Корень проблемы

Высоты на corners перераспределяются кривой `e = 1 − √(1 − x)` (`ValueRedistributor.RedistributeElevation`,
уклон в сторону низин — мало вершин). Затем `CellClimateAverager.ApplyToCells` **усредняет** все corners клетки
в одно значение — усреднение стягивает значения к середине, и разброс высот на клетках (именно его использует
рендер для hillshade и поясов) сжимается → рельеф вялый.

### Изменение — контраст вокруг середины на клетке

В `CellClimateAverager.ApplyToCells`, **после** усреднения и **до** классификации биома:

```csharp
float avgElevation = cellCorners.Average(c => c.Elevation);
avgElevation = Math.Clamp(0.5f + (avgElevation - 0.5f) * elevationContrast, 0f, 1f); // NEW
...
cell.Height = avgElevation;
cell.Biome  = BiomeClassifier.Classify(avgElevation, avgMoisture, cell.IsOcean, isLake);
```

- Низины уходят ниже, вершины выше → выразительный рельеф и контрастный hillshade в рендере.
- Применяется **до** `Classify`, поэтому биомы отражают усиленный рельеф (чуть больше высокогорья/голых вершин —
  принято как ожидаемое следствие). Так же затрагивает температуру (`cell.Height` кормит охлаждение с высотой) —
  согласованно.
- Новый параметр `ElevationContrast` (float, дефолт **1.5**, разумный диапазон 1.0–2.5). Прокидывается из
  `WorldGenerator` (оба пути) в `ApplyToCells` как аргумент.

## A3. Пляж — тонкий гарантированный поясок

### Корень проблемы

`BiomeClassifier.Classify` метит `Biome.Beach` по `elevation < beachElevationThreshold (0.1)` — по высоте, а не по
берегу. При усиленном контрасте высот (A2) это ещё и налепит «пляжи» во внутренних низинах.

### Изменение — пляж по смежности с океаном

1. **Убрать высотное правило пляжа** из `BiomeClassifier.Classify`: удалить ветку
   `if (elevation < beachElevationThreshold) return Biome.Beach;`. Beach больше не зависит от высоты. Параметр
   `beachElevationThreshold` становится неиспользуемым → удалить его из сигнатуры `Classify`, из вызова в
   `CellClimateAverager.ApplyToCells`, и из `GenerationParams` (осознанный ripple по сигнатурам).
2. **Новый шаг `BeachClassifier`** (`Assets/WorldGen/Generation/BeachClassifier.cs`), вызывается **после**
   `CellClimateAverager` в обоих путях `WorldGenerator`:

```csharp
public static class BeachClassifier
{
    /// Клетка суши, у которой хоть один сосед — океан, становится Biome.Beach.
    /// Непрерывный кант в 1 клетку по всему океанскому берегу, независимо от высоты.
    /// Озёрные берега НЕ трогаем (пляж только против океана — по требованию).
    public static void AssignCoastalBeaches(List<VoronoiCell> cells)
    {
        var byId = cells.ToDictionary(c => c.Id);
        foreach (var cell in cells)
        {
            if (cell.IsOcean || cell.Biome == Biome.Lake) continue; // только суша
            bool coastal = cell.NeighborIds.Any(id =>
                byId.TryGetValue(id, out var n) && n.IsOcean);
            if (coastal) cell.Biome = Biome.Beach;
        }
    }
}
```

- Данные уже есть: `cell.NeighborIds` + сосед `IsOcean` (проставлен ранее `CellWaterAssigner`).
- Порядок: строго **после** классификации биома (перезаписывает берег) и **до/независимо от** роста регионов
  (пляж — это суша, `!IsOcean`, участвует в регионах как обычно) и температуры (не зависит от биома).
- **Мягкий переход песок→биом** по coast-distance — это уже подпроект B (рендер), здесь только гарантируем
  классификацию. Пляж по всему берегу единый (песок), биом-зависимый берег (камни на холодном берегу и т.п.) —
  возможная будущая доработка, в этот spec не входит.

## Порядок пайплайна (итог)

Изменённый фрагмент `WorldGenerator` (оба пути), новое **выделено**:

```
... island shape (HeightmapGenerator с новым falloff) ...   ← A1
... ocean/lake flood fill, lake filter, water на клетки ...
... elevation (distance+noise), RedistributeElevation ...
... moisture ...
CellClimateAverager.ApplyToCells(cells, corners, ElevationContrast)  ← A2 (контраст внутри)
BeachClassifier.AssignCoastalBeaches(cells)                          ← A3 (NEW шаг)
... регионы, унификация озёр, температура ...
```

В `GenerateWorldStepped` новый шаг A3 садится в Step 4/6 «Расчёт биомов», сразу после `ApplyToCells`.

## Обратная совместимость

- Модель данных клетки не меняется — новых персистентных полей у `VoronoiCell` нет. Старые `.dndproj` загружают
  сохранённые клетки и рисуются как раньше; новую логику видят только **новые** генерации.
- **Проверить на этапе плана:** что сейв действительно хранит клеточные данные (Height/Biome/IsOcean/...), а не
  только `GenerationParams` с перегенерацией при загрузке. По памяти проекта — хранит клетки (старые сейвы грузятся
  без изменений), но это надо подтвердить чтением кода сериализации до реализации.
- Удаление `BeachElevationThreshold` из `GenerationParams` — если этот параметр где-то сериализуется в сейве
  настроек, убедиться, что его исчезновение не ломает десериализацию (скорее всего `GenerationParams` не
  сериализуется целиком; подтвердить в плане).

## Проверка (self-тесты, конвенция проекта)

- **Falloff — океан по краям:** для нескольких сидов `HeightmapGenerator.GetHeight` в 4 серединах рёбер карты
  `< SeaLevel` (вода гарантирована по периметру). Плюс детерминизм (один сид → один результат).
- **Falloff — радиальность:** в (смещённом) центре falloff ≈ 0; в серединах рёбер falloff ≈ 1.
- **Доля суши в разумных пределах:** грубая сетка выборки — доля суши в коридоре ~30–70% (материк крупный, но не
  весь квадрат и не крошечный островок). Защита от «слишком много воды / слишком мало».
- **ElevationContrast расширяет диапазон:** на наборе значений контраст > 1 увеличивает разброс min–max
  относительно контраста = 1.
- **BeachClassifier:** фикстура (кольцо океанских клеток вокруг суши) — прибрежные клетки суши → `Beach`,
  внутренние клетки суши → не `Beach`, ни одна водная клетка (ocean/lake) не становится `Beach`.

Хост self-тестов (пустой MonoBehaviour с `[ContextMenu]` как в остальном проекте, либо существующий тест-объект
генерации) выбирается в плане. Компиляцию проверяет Unity Editor (агенты Unity не запускают).

## Риски и открытые вопросы

- **Джиттер центра → материк у края.** Смягчено: джиттер ≤ 0.2, falloff всё равно топит рёбра. Если на практике
  край иногда «прилипает», уменьшить `ContinentCenterJitter` или добавить hard-guard (гарантированный водный
  бордюр в N% у самой границы). Пометить при тюнинге в Editor.
- **ElevationContrast прижимает много клеток к 0/1 (clamp).** Умеренный дефолт 1.5 этого избегает; при драматичных
  значениях возможна потеря деталей на хвостах — ожидаемо, это ручка пользователя.
- **Удаление `beachElevationThreshold`** — ripple по сигнатурам `Classify`/`ApplyToCells`/`GenerationParams`.
  Осознанно; альтернатива (оставить мёртвый параметр) грязнее.
- **Радиальная метрика без toggle.** Квадратная форма была сознательным «заполнить прямоугольник» выбором; мы его
  заменяем. Возврата не оставляем (YAGNI). Если материк-квадрат когда-то понадобится — вернуть через git.
- **Тюнинг — итеративный в Editor.** Точные дефолты `InnerRadius/FalloffPower/CoastRoughness/...` — стартовые;
  финальные подбираются визуально в Play mode (агент их не увидит, подбор интерактивный с пользователем).

## Вне объёма (следующие подпроекты)

- **B (векторный рендер):** группировка клеток по «биом + пояс высоты», кривые-контуры из вершин полигонов,
  плоская заливка + внутренний hillshade, **мягкий переход песок→биом** по coast-distance, холодная единая
  палитра, спокойное свечение берега, финальная состыковка тона фон↔океан.
- **C (декорации):** иконки (биом/рельеф), подписи регионов, рамка/компас/масштаб.
