# Кривые границы биомов и полос высоты + округлость контуров — дизайн

**Дата:** 2026-07-07
**Ветка:** `map-terrain-raster`
**Статус:** одобрено, готово к плану

## Проблема

В плоской заливке (`FlatRegionFill`, режим Combined + SmoothBorders) и цвет семейства биома,
и полоса высоты берутся из **ближайшей** клетки Вороного напрямую
(`MapRasterizer.ColorForLandPixelFlat`): семейство — через `FlatFamilyColor`, полоса — через
`(int)(cell.EffectiveElevation * ElevationBands)`. Поэтому обе границы (между биомами и между
полосами высоты) идут ровно по рёбрам полигонов Вороного — «гранёные». Берег уже сглаживается
отдельно, через маску `IsLand` (`CoastlineContour`), но внутренние границы — нет.

Цели:
1. **Сделать границы биомов кривыми** — так же, как берег.
2. **Сделать границы полос высоты кривыми** — тем же способом.
3. **Округлить контуры** (берег, биомы, полосы) — строить кривую не по всем вершинам полигонов,
   а по части, чтобы радиусы были крупнее.

## Охват

- **Только плоская заливка** (Combined + SmoothBorders + `FlatRegionFill`). В блендинг-режиме
  границы и так размыты переходом — трогать не будем.
- **Подход A**: маски по категориям (переиспользуем механику контура берега), применённый к
  **двум** категориальным полям суши — семейство биома и полоса высоты.
- **Настройки сглаживания/округлости — общие** для берега, биомов и полос (не раздельные).
- **Вне охвата:** блендинг-режим; раздельные настройки берег/биомы/полосы.

## Подход A: маски по категориям

Обобщаем: «сгладить категориальное поле над сушей» — трассируем границы между категориями так
же, как берег трассирует «вода/не-вода», сглаживаем + прорежаем, растеризуем в попиксельный
буфер-метку. Механизм один, вызывается **дважды** — для семейств и для полос высоты.

### Обобщённая трассировка контура

`CoastlineContour.TraceSmoothedLoops` сейчас жёстко зашит на предикат «вода/не-вода»
(`IsWaterCell`). Обобщаем: предикат категории клетки — параметр `Func<VoronoiCell,bool>
inRegion`. Берег остаётся частным случаем (`inRegion = IsWaterCell`). Трассировка,
`boundaryNeighbors`, `WalkClosedLoop`, замыкание петель — те же; отличается только критерий
«ребро — граница» (две смежные клетки различаются по `inRegion`).

### Прореживание перед Чайкином (цель 3)

Новый шаг перед `ChaikinSmoothClosed`: прорежаем петлю по длине дуги — идём по вершинам, копим
длину вдоль контура, оставляем вершину каждые `minSegmentDistance` мировых единиц. Реже вершины
→ крупнее радиусы дуг Чайкина → круглее граница. Применяется **и к берегу, и к биомам, и к
полосам** (один код).
- **Защита от схлопывания:** петли с ≤ 8 вершинами не прорежаем вовсе (мелкие острова, узкие
  полоски). Прореживание никогда не оставляет < 4 вершин (валидный замкнутый полигон).
  `minSegmentDistance = 0` → прореживание не делается (текущее поведение).
- Важно: просто «больше итераций Чайкина» НЕ округляет сильнее — кривая сходится к сплайну того
  же опорного многоугольника, на каждой исходной вершине остаётся бугорок. Округляет только
  выброс опорных точек.

### Растеризация в разметку

Новый метод `CoastlineContour.RasterizeRegionLabel(loops, label[], labelValue, ...)` — как
`RasterizeIsLand` (even-odd scanline), но пишет `labelValue` **только там, где пиксель внутри**
петли, не затирая внешние пиксели. Позволяет растеризовать категории последовательно в один
буфер.

### Обобщённый проход (вызывается дважды)

Помощник `MapRasterizer.RasterizeSmoothedCategoryRect(...)`:
- вход: буфер-метка `int[]`, функция `categoryOf(cell) → int` (`-1` = исключить, напр. вода),
  список категорий в порядке приоритета (младший → старший), rect.
- сбрасывает буфер-метку в прямоугольнике на `-1`;
- собирает категории, встречающиеся в прямоугольнике + запас (по `CellId` через `categoryOf`,
  исключая `-1`);
- для каждой присутствующей категории **в порядке приоритета по возрастанию**: трассирует петли
  с предикатом `cell => categoryOf(cell) == category`, прорежает + Чайкин, растеризует метку.
  Старшая категория перезаписывает младшую на перекрытиях (последний растеризованный выигрывает).

Два вызова в `BakeFieldsRect` (только `painted && FlatRegionFill && SmoothRegionBorders`):

1. **Семейства → `FamilyLabel`.** `categoryOf(cell) = land ? (int)GetFamily(biome) : -1`.
   Порядок приоритета (младший → старший, старший рисуется позже и выигрывает; характерные
   семейства сверху, чтобы их дуги читались чётко):
   ```
   Plains, Moor, Forest, ForestWarm, Coast, Tundra, Highland, Badlands, Snow
   ```
2. **Полосы высоты → `BandLabel`** (только если `ElevationBands > 1`).
   `categoryOf(cell) = land ? Clamp((int)(EffectiveElevation*ElevationBands), 0, ElevationBands-1)
   : -1`. Порядок приоритета = индекс полосы по возрастанию (выше = сверху).

`land = !(cell.EffectiveIsOcean || cell.EffectiveIsLake)` — регионы категорий ограничены сушей,
чтобы упирались в берег.

### Цвет пикселя

В `ColorForLandPixelFlat`:
```
// базовый цвет семейства
int fLabel = config.SmoothRegionBorders ? buffers.FamilyLabel[idx] : -1;
Color32 fam = config.ShowBiomeLayer
    ? (fLabel >= 0 ? MapPalette.GetSlotColor(config.Theme, (BiomeFamily)fLabel)  // сглаженная разметка
                   : FlatFamilyColor(config.Theme, cell.Biome))                  // откат: ближайшая клетка
    : new Color32(209, 199, 166, 255);

// полоса высоты
if (config.ShowReliefLayer && config.ElevationBands > 1) {
    int band = config.SmoothRegionBorders ? buffers.BandLabel[idx] : -1;
    if (band < 0) band = Mathf.Clamp((int)(cell.EffectiveElevation * config.ElevationBands),
                                     0, config.ElevationBands - 1);              // откат
    ... factor как сейчас ...
}
```
Обводка берега, зерно — без изменений.

Приоритет влияет только на то, **чья кривая** становится видимой границей на общем стыке двух
категорий — целые регионы от него не исчезают. Порядки семейств — настраиваемая константа в коде.

## Управление (инспектор WorldMapRenderer)

- `coastlineSmoothness` (уже есть, `[Range(0,5)]`, Chaikin) — **теперь применяется к берегу,
  биомам и полосам** (имя поля сохраняем во избежание сброса сериализованного значения; семантика
  расширена, тултип обновить).
- **новый** `borderRoundness` `[Range(0f,3f)]`, дефолт `1f` — сила прореживания (берег + биомы +
  полосы). `0` = как сейчас. Резолвится в `BuildRasterConfig`:
  `BorderRoundnessDistance = borderRoundness * minPointDistance` (мировые единицы, чтобы не
  зависеть от разрешения — `minPointDistance` ≈ размер клетки).
- **новый** `smoothRegionBorders` (toggle), дефолт `true` — сглаживать границы биомов и полос
  (быстро сравнить кривые/грани и запасной выключатель, если клинья на стыках мешают).

## Изменения структуры данных

- `MapRasterBuffers`: `+ int[] FamilyLabel`, `+ int[] BandLabel` (размер n; в `CreateEmptyBuffers`).
- `MapRasterConfig`:
  - `+ bool SmoothRegionBorders`, дефолт `false` (в конфиге). Как у `FlatRegionFill`: дефолт в
    конфиге `false`, чтобы существующие самотесты плоской заливки (не задающие поле) шли прежним
    путём «ближайшая клетка». Пользовательский дефолт `true` — у сериализованного
    `WorldMapRenderer.smoothRegionBorders`.
  - `+ float BorderRoundnessDistance`, дефолт `0f` (без прореживания) — та же логика: существующие
    самотесты берега/паритета (`CoastlineSmoothness=0`) остаются точными.

## Производительность / живая кисть

- Трассировка петель глобальна (как у берега сейчас — дёшево, масштаб числа клеток, не пикселей).
- На мазке для каждого поля трассируем **только категории, встречающиеся в прямоугольнике мазка +
  запас** — остальные не могут дать метку в этом прямоугольнике. Обычно 1–3 семейства + 1–3
  полосы → стоимость ≈ ×(2–6) от берега на мазок. Полный ребейк трассирует все категории — он не
  интерактивный.
- `ComputeTouchedPixelRect`: расширить `pad` на `BorderRoundnessDistance` (граница может сдвинуться
  на величину прореживания при правке кистью).

## Риски / компромиссы

- **Клинья на тройных стыках** трёх категорий: маски, сглаженные независимо, не стыкуются идеально
  → пиксель может остаться с меткой `-1` → откат к ближайшей клетке (тонкая гранёная каёмка, почти
  скрыта обводкой/зерном). Не краш. Действует и для семейств, и для полос.
- **Сильное прореживание** может съесть мелкие острова/полоски — защита минимумом вершин (≤ 8 не
  прорежаем, не ниже 4). Высокая округлость намеренно упрощает форму.
- **Замкнутость петель категорий** опирается на океан по краю карты (как берег: falloff топит
  край). Категория суши, дотягивающаяся до сырого края карты, дала бы разомкнутую петлю →
  `WalkClosedLoop` вернёт `null` → петля пропускается → этот регион остаётся гранёным (откат),
  без краша.
- **Полосы и семейства сглажены независимо** — их кривые границы не совпадают (это разные данные,
  так и должно быть).
- **Стоимость** ×(число категорий у кисти) от берега — смягчено пропуском отсутствующих категорий.

## Тестирование (ContextMenu-самотесты в WorldMapRenderer)

Среда без пакетной компиляции (проект открыт в Editor) — самотесты ручные, ревью построчное.

1. **Прореживание уменьшает вершины.** Петля с частыми вершинами + `minSegmentDistance > 0` →
   вершин меньше; петля с ≤ 8 вершинами не меняется (защита); не ниже 4.
2. **Разметка семейств сглажена.** Фикстура из двух семейств → пиксели получают верную метку;
   граница смещена от сырого ребра клетки (кривая), а не строго по нему.
3. **Разметка полос высоты сглажена.** Фикстура с двумя полосами высоты → `BandLabel` даёт верную
   полосу; граница кривая; при `ElevationBands ≤ 1` проход полос пропускается (все `-1`).
4. **Приоритет на перекрытии.** Фикстура, где маски двух категорий перекрываются → выигрывает
   старшая по порядку приоритета.
5. **Откат на клине.** Пиксель без метки (`-1`) → семейство/полоса из ближайшей клетки, водная
   ближайшая клетка → `FlatFamilyColor` (Coast), без краша.
6. **Регрессия: одна категория.** Вся суша одного семейства/одной полосы → сплошная разметка, без
   внутренних границ, без краша; вода не затронута.
7. **Округлость всех трёх.** `BorderRoundnessDistance > 0` уменьшает число вершин в петле берега, в
   петлях семейств и в петлях полос.
