# Дизайн: POI-медальоны (sub-project C, часть 2)

Дата: 2026-07-09
Статус: утверждён в брейншторме, готов к плану
Эталон: `design_handoff_realmweaver_map/` (Terra Umbrarum), раздел «POI Markers»

## Контекст

В приложении уже есть POI-система: `PoiData` (тип/имя/описание/позиция/кастом-иконка),
`PoiManager` (world-space маркеры), `PoiMarkerView` (`SpriteRenderer` + `TextMesh`), и
**`PoiPlaceholderFactory.GetPlaceholder(PoiType)`** — единая точка, которая печёт 64×64 спрайт
на тип и кэширует; спрайт используется **в трёх местах**: маркеры на карте, строки списка POI,
кнопки типов в панели редактирования. Сейчас спрайт = цветной круг + тёмная обводка + 7×7
белая пиктограмма, 5 типов.

Эта спека апгрейдит POI до **дизайна медальонов** из хэндоффа (11 типов) — тёмный диск со
свечением, акцентное кольцо, процедурная иконка в каменных тонах по центру. Апгрейд `GetPlaceholder`
автоматически обновляет все три места использования.

Sub-project C в целом: iso-декорации (часть 1, СЛИТО) → **POI-медальоны (эта спека)** →
region-лейблы+хром → fog of war (отдельные спеки).

## Ключевые решения (из брейншторма)

1. **Все 11 типов** из хэндоффа (не подмножество).
2. **Иконки — богаче** (ближе к мокапу: замок+флаг, три башни, колоннада, якорь…), процедурные
   per-type, но всё ещё плейсхолдеры (заменяемы через существующий `CustomIconBytes`).
3. **Рамка медальона** — общая, аккуратная (свечение/диск/ободок/акцентное кольцо).
4. **Акцент фиксированный** (тёплое золото `#e6b25c`), тема-независимо (нет рантайм-свитчера тем;
   кэш по типу остаётся простым). Привязка к `paletteTheme` — возможная будущая итерация.
5. **Расширение `PoiType` — только append** (int-сериализация, обратная совместимость сейвов).

## Модель данных / обратная совместимость

`ProjectSerializer` использует Newtonsoft **без `StringEnumConverter`** → `PoiType` сериализуется
как **int**. Поэтому enum расширяется **строго добавлением в конец**, существующие значения не
двигаются:

```csharp
public enum PoiType
{
    Unknown = 0, City = 1, Ruin = 2, Dungeon = 3, Fortress = 4,   // существующие — НЕ ТРОГАТЬ
    Village = 5, Tower = 6, Temple = 7, Encounter = 8, Camp = 9, Port = 10  // новые
}
```

`Unknown` = хэндоффский «default» (неназначенная точка). `PoiData` не меняется —
`CustomIconBytes`/`CustomSpritePath` (замена иконки на свою) работают поверх нового плейсхолдера.
Старые `.dndproj` грузятся без изменений (их type-int 0–4 → те же значения); новые типы 5–10 просто
не встречались в старых сейвах. Явные int-значения в enum — защита от случайного переупорядочивания.

## Спрайт медальона (`PoiPlaceholderFactory`)

Апгрейд `Build(PoiType)`; публичный `GetPlaceholder(type)` + кэш по типу — без изменений сигнатуры.

- **Резолюция**: 64→**128 px**; фильтр `Point`→**`Bilinear`** (градиент/свечение требуют интерполяции).
  Формат `RGBA32` (SetPixels/цветные данные, sRGB — как сейчас).
- **Рамка медальона** (общая, рисуется для всех типов; радиус `R = size/2`):
  1. **Мягкое внешнее свечение** — тёмное, радиальный спад альфы к краю (за диском).
  2. **Радиальный диск-градиент** — центр `#141c25` → край `#080d14`.
  3. **Тёмный ободок** — кольцо толщиной ~`2.6·(size/64)` px, цвет `#0a0d12` (чёрный камень).
  4. **Акцентное кольцо** — тонкое (~`1.6·(size/64)` px) кольцо цвета accent `#e6b25c`.
- **Иконка** (per-type, каменные тона): `dark #2b323d`, `light #414c5b`, `black #0a0d12`,
  `steel #c9d2dc`, `wood #4a3a28`; accent `#e6b25c` на флагах. Рисуется процедурно в свой tile,
  измеряется bbox непрозрачных пикселей, масштабируется так, чтобы **диагональ bbox ≈ 2R·0.82**,
  и центрируется в диске.
- **11 рисовалок иконок** (switch, как `DecorationPlaceholderFactory`):
  | Тип | Иконка |
  |---|---|
  | Unknown | accent-«?» глиф (неназначенная) |
  | City | зубчатый кип (крепостной дом) + флаг |
  | Fortress | три башни (центральная выше) + флаг |
  | Village | два дома с двускатными крышами |
  | Tower | одиночная зубчатая башня + флаг |
  | Temple | симметричная колоннада + треугольный фронтон |
  | Ruin | две сломанные колонны + упавшая притолока на земле |
  | Dungeon | каменные врата с тёмной аркой + решётка-портикул |
  | Encounter | скрещённые стальные мечи |
  | Camp | симметричный шатёр + скрещённые шесты на вершине |
  | Port | якорь |
- **Акцент** — константа `#e6b25c` (не из темы). **Кэш по типу** сохраняется (фикс-палитра → без
  ключа темы).

Иконки — процедурные примитивы (прямоугольники/линии/треугольники/дуги), достаточно детальные для
читаемости на карте, но всё ещё плейсхолдер: финальный арт заменяется per-POI через `CustomIconBytes`
(уже есть) или позже — заменой рисовалок.

## UI

- **`PoiEditPanel` — пикер типов**: сейчас 4 хардкод-`AddTypeButton` (Город/Руины/Подзем./Креп.) в
  ряд. Заменить на **грид icon-кнопок** по всем **10** присваиваемым типам (не-Unknown), графика
  кнопки = `GetPlaceholder(type)` (медальон) + короткая подпись; `GridLayoutGroup` ~4–5 в ряд.
  Существующие `typeButtons`-словарь + `ApplyTypeHighlight(type)` расширяются на новые типы; проводка
  `poiManager.UpdatePoiType(id, type)` не меняется.
- **`PoiToolPanel`**:
  - `TypeName(PoiType)` дополнить всеми 11: City→«Город», Ruin→«Руины», Dungeon→«Подземелье»,
    Fortress→«Крепость», Village→«Деревня», Tower→«Башня», Temple→«Храм», Encounter→«Встреча»,
    Camp→«Лагерь», Port→«Порт», Unknown→«Точка».
  - Фильтр-чипы: «Все» + по чипу на каждый тип (перенос по строкам, как сейчас 2 ряда → больше рядов).
    Логика фильтра (`filterType`, `poi.Type != filterType`) не меняется.

## Тестирование / персистентность

Агенты не запускают Unity → `[ContextMenu]`/self-tests гоняет юзер; визуал — юзер в Editor.

- **Обратная совместимость сериализации** (расширить `ProjectSerializerSelfTests`): round-trip
  `PoiData{Type=Fortress}` (int 4, существующий) и `PoiData{Type=Port}` (int 10, новый); а также
  десериализация «старого» JSON с `"Type": 4` → `Fortress`. Подтверждает, что append-only не сломал
  формат.
- **`PoiPlaceholderFactory`**: `GetPlaceholder(t)` для всех 11 типов — не null, размер 128×128,
  и спрайты попарно различны (напр. хеш пикселей отличается) — ловит забытую/дублированную рисовалку.
- **Визуал (юзер, Editor)**: 11 медальонов в пикере панели + на карте — рамка (свечение/диск/ободок/
  акцентное кольцо) + иконки читаются и различимы; кастом-иконка (`CustomIconBytes`) по-прежнему
  перекрывает медальон.

## Интеграция / точки касания

- `PoiData.cs` — enum (+6 значений, явные int).
- `PoiPlaceholderFactory.cs` — рамка + 11 рисовалок + 128px/Bilinear.
- `PoiEditPanel.cs` — грид icon-кнопок типов.
- `PoiToolPanel.cs` — `TypeName` + фильтр-чипы.
- `ProjectSerializerSelfTests.cs` — round-trip новых типов.
- НЕ трогаем: `PoiManager`/`PoiMarkerView` (используют `GetPlaceholder` как есть), `PoiData` поля,
  формат сериализации.

## Персистентность

Формат `.dndproj` не меняется (тот же `PoiData`, enum-int append-only). Старые сейвы грузятся;
новые типы сохраняются/грузятся как int 5–10. Миграции не нужно.

## Вне области (отдельные спеки/итерации)

- Привязка акцента медальона к активной `paletteTheme` (сейчас фикс-золото).
- Region-лейблы + хром (компас/масштаб/картуш/рамка), fog of war — отдельные куски sub-project C.

## Риски

- **Сериализация enum (проект кусало 3× на namespace/serialization):** значения `PoiType` НЕ
  переупорядочивать; только append + явные int. Self-test round-trip старого+нового типа обязателен.
- **UI на 11 типов**: грид пикера и ряд фильтр-чипов должны влезать в текущие ширины панелей
  (пикер `308`, список `262` — см. UI-хэндофф); проверить перенос/скролл, не ломая layout.
  Юзер визуально верифицирует.
- **Читаемость мелких иконок**: на реальном зуме карты медальон ~24–34 px — детальные иконки могут
  «слипаться»; рисовать с запасом контраста (каменные тона на тёмном диске), юзер оценивает на карте.
