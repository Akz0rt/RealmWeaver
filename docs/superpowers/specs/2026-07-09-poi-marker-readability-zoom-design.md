# Дизайн: читаемость иконок POI + масштаб маркеров по зуму

Дата: 2026-07-09
Статус: утверждён (2 решения выбраны юзером), готов к исполнению
Ветка: `feat/poi-medallions` (правки поверх POI-медальонов, до мержа в main)
Контекст: юзер визуально проверил медальоны в Editor (вёрстка UI — OK) и дал два замечания:
(1) иконки внутри медальонов нечитаемы; (2) маркеры должны масштабироваться по зуму, чтобы
на любом приближении быть хорошо видимыми.

## Первопричины (по коду)

Иконки нечитаемы из-за трёх вещей в `PoiPlaceholderFactory` (Task 2):
1. **Мелкие** — рисуются в фиксированных координатах ~48px в 128px-диске (~44% интерьера). Шаг спеки
   «измерить bbox непрозрачных пикселей и вписать в ~80% диска» в реализацию не попал.
2. **Тонкие штрихи** — линии 1–2px (`VLine`/`HLine`/одиночные `Px`: колонны, мечи, решётка) при
   даунскейле до ~30px + `FilterMode.Bilinear` превращаются в кашу.
3. **Низкий контраст** — тона тела `Dark #2b323d`/`Light #414c5b` почти сливаются с центром диска
   `#141c25`. Пробиваются только `Steel #c9d2dc` и `Acc #e6b25c`.

Маркер не масштабируется: `PoiMarkerView` — мировой `SpriteRenderer` фиксированного размера
(`PoiManager.iconWorldSize=36`). Камера ортографическая (`MapCameraController.targetCamera`,
`orthographicSize` в диапазоне `[naturalFitSize·0.08 … naturalFitSize·3]`, `naturalFitSize=maxSide·0.7`).
Экранный размер маркера = `worldSize/(2·orthoSize)·ScreenHeight` → при отдалении мельчает,
при сильном приближении раздувается.

## Решение 1 — масштаб маркеров по зуму (частичный + clamp) [ВЫБРАНО]

Экранный размер маркера частично реагирует на зум (демпфированно), но зажат в читаемую полосу px.

Формула (демпфирование степенью `k`, затем clamp по экранным px), считается в `PoiManager.LateUpdate`
один раз за кадр (только если `orthographicSize` изменился) и раздаётся всем маркерам:

```
refSize = cameraController.NaturalFitSize            // 100%-fit размер; при нём маркер = «как сегодня»
factor  = Pow(orthoSize / refSize, zoomScaleExponent) // k=0: мировой-фикс (текущее); k=1: пост. экранный
basePx  = iconWorldSize · factor · (Screen.height / (2·orthoSize))  // экранные px маркера базового масштаба
factor *= Clamp(basePx, minMarkerScreenPx, maxMarkerScreenPx) / basePx  // зажать в читаемую полосу
// → каждому маркеру: ApplyZoomScale(factor)
```

- `k = zoomScaleExponent = 0.5f` — частичная реакция (маркер немного растёт при приближении, мельчает
  при отдалении, но не 1:1). Серилизуется на `PoiManager`, крутится в Инспекторе.
- Полоса `minMarkerScreenPx = 26f`, `maxMarkerScreenPx = 64f` — маркер никогда не мельче/крупнее.
  При 100% (`orthoSize=refSize`, `factor=1`) базовый px ≈ сегодняшний и попадает внутрь полосы →
  вид на 100% не меняется.
- Ниже минимума на сильном отдалении и выше максимума на сильном приближении clamp удерживает размер.
- `factor` (безразмерный множитель к базовому мировому размеру) применяется к иконке И подписи маркера
  синхронно (подпись не «отстаёт»); смещение подписи пересчитывается от эффективного размера иконки.
- Per-POI `IconScale`/`LabelScale` домножаются поверх `factor` (юзерский множитель может выйти за clamp —
  это намеренно; clamp держит ДЕФОЛТНЫЙ маркер).

Разрешение камеры: `PoiManager` берёт `MapCameraController` (ссылка в Инспекторе или
`FindObjectOfType`, кэш) → `.targetCamera` + `.NaturalFitSize` (публичное; 0 до первой генерации →
пропускаем кадр, маркеры остаются `zoomScale=1` = текущее поведение). `naturalFitSize` учитывает размер
карты, поэтому clamp по px делает поведение стабильным между картами разного размера.

### Точки касания (Решение 1)
- `PoiManager.cs` — поля `cameraController`, `zoomScaleExponent`, `minMarkerScreenPx`, `maxMarkerScreenPx`;
  `LateUpdate` считает `factor` и раздаёт (кэш last-ortho для скипа неизменённых кадров).
- `PoiMarkerView.cs` — поле `float zoomScale=1f`; `ApplyZoomScale(float)` сохраняет и переприменяет размер;
  сайзинг вынесен в `ApplySizing()` (иконка `localScale`, подпись `characterSize`, смещение подписи —
  все × `zoomScale`), вызывается из `Refresh()` и `ApplyZoomScale()`.

## Решение 2 — читаемые иконки (крупные жирные силуэты, концепты сохранить) [ВЫБРАНО]

Переработка отрисовки иконок в `PoiPlaceholderFactory` (рамка медальона — БЕЗ изменений). Концепты
по типам сохраняются (замок+флаг, три башни, колоннада, якорь…), но рисуются крупно, толсто, светло.

**Три правки от первопричин:**

1. **Вписывание (auto-fit, из спеки).** Каждая иконка рисуется в scratch-буфер `Color32[128²]` своей
   per-type рисовалкой; попутно трекается bbox непрозрачных пикселей. Затем один общий блит вписывает
   bbox в ~80% интерьера диска, центрируя:
   ```
   targetDiag = (2·rAccIn)·0.80              // ~80% диаметра интерьера диска
   s = targetDiag / sqrt(bboxW² + bboxH²)    // масштаб
   (bcx,bcy) = центр bbox
   для каждого dest (x,y) в интерьере диска:
       srcX = bcx + (x - discCx)/s;  srcY = bcy + (y - discCy)/s
       c = scratch[nearest(srcX,srcY)];  если c непрозрачный → medallion[x,y] = c
   ```
   Nearest-neighbor (финальная текстура и так Bilinear-фильтруется при показе). Так все 11 иконок
   получают одинаковый крупный фил независимо от исходных координат рисовалки.

2. **Толстые штрихи.** Примитивы-линии рисуются полосой ≥5–6px в scratch (толщина как параметр:
   `HBar`/`VBar`/`Stroke` вместо 1px `HLine`/`VLine`), чтобы после вписывания оставаться ≥~4px и
   не исчезать при даунскейле.

3. **Высокий контраст (светлый тон).** Тело иконки — светлое, пробивается на тёмном диске:
   - `IcoLight = #c9d2dc` — основной силуэт (постройки/металл).
   - `IcoShade = #6a7480` — вторичная тень/глубина внутри иконки (всё ещё светлее диска).
   - `IcoEdge  = #05080d` — тонкая тёмная обводка вокруг силуэта (пост-проход: непрозрачный
     icon-пиксель, граничащий с фоном диска, получает тёмный кант) — резкость на мелком размере.
   - `Acc = #e6b25c` — золото на флагах/ключевых акцентах (как раньше).
   - `Wood = #7a5c3a` — осветлённое дерево (шесты шатра и т.п.), если нужно.
   Старые `Dark/Light` как основной цвет тела НЕ используются (сливаются с диском).

Иконки остаются процедурными плейсхолдерами — заменяемы per-POI через `CustomIconBytes` (шов есть) или
позже заменой рисовалок. Кэш по типу и сигнатура `GetPlaceholder(PoiType):Sprite` — БЕЗ изменений.
128px/RGBA32/Bilinear — без изменений.

### Точки касания (Решение 2)
- `PoiPlaceholderFactory.cs` — новая палитра иконок; `Stroke`/`HBar`/`VBar` (толстые примитивы);
  per-type рисовалки в scratch (концепты сохранены, крупнее/толще/светлее); общий `FitIcon` блит
  (bbox → 80% диска) + опц. пост-обводка `IcoEdge`. `DrawFrame`, `Build`, `GetPlaceholder`, кэш — как есть.

## Тестирование / персистентность
- Формат не меняется, `PoiData`/сериализация не трогаются. Существующий `SelfTestPlaceholderFactory`
  (128px + различность + кэш) должен остаться PASS (иконки крупнее, но 128×128 и попарно различны).
- Юзер (Editor): (1) `SelfTest: POI Placeholder Factory` → PASS; (2) визуально — 11 иконок читаемы и
  различимы в пикере/на карте, светлые на тёмном диске; (3) зум колесом — маркеры остаются читаемыми
  на всём диапазоне, не исчезают и не раздуваются; ползунки `zoomScaleExponent`/`min/maxMarkerScreenPx`
  дают ожидаемый эффект; (4) `CustomIconBytes` по-прежнему перекрывает медальон.

## Вне области
- Финальный арт вместо процедурных иконок (шов `CustomIconBytes`).
- Кластеризация/скрытие перекрывающихся маркеров на сильном отдалении (плотность) — отдельно, если нужно.
- Рестайл подписей (Cinzel/золото), привязка акцента к теме — как в основной POI-спеке, вне области.

## Риски
- **Auto-fit блит** — единственная новая нетривиальная логика; специфицировать точно (nearest-sampling,
  границы bbox, деление на 0 при пустом bbox — guard `bboxDiag>0`). Юзер верифицирует визуально.
- **Экранный clamp** зависит от `Screen.height`/`orthoSize`/`NaturalFitSize` — guard на `NaturalFitSize>0`
  и `orthoSize>0`; до первой генерации маркеры = `zoomScale=1`.
- **Читаемость** финально оценивает юзер на реальном зуме; ожидается подстройка параметров (ползунки).
