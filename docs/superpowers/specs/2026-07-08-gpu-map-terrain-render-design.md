# GPU-рендер террейна карты — Design

**Статус:** одобрено (брейншторм 2026-07-08).
**Ветка:** `map-terrain-raster` (переархитектура подпроекта 1 — растровой заливки — на GPU).

## Проблема

Вид карты (тёмное фэнтези: палитра, сглаженные границы, рельеф, свечение берега, зерно, виньетка) сейчас **целиком вычисляется на CPU в один поток** (`MapRasterizer`) и пишется в `Texture2D` через `SetPixels32`/`Apply`. GPU лишь показывает готовую текстуру (`Sprites/Default`). По сути — софтверный рендерер на одном ядре.

Замеры кисти (после оптимизаций A+B этой сессии) на большой кисти (rect ~510×510, текстура 2048²):

| подстоимость | мс | тип |
|---|---|---|
| `color`+виньетка | ~63–71 | попиксельно |
| `coastDist` | ~40–45 | попиксельно |
| `trace` (Чайкин по петлям) | ~20–30 | геометрия |
| `raster` (заливка) | ~25 | геометрия |
| **штамп целиком** | **~160** | → ~6 fps |

Попиксельная работа (`color`, `coastDist`) масштабируется с площадью rect и упирается в одно ядро CPU. Требование: **≥25–30 fps, лучше больше**, при любом размере кисти. На одном ядре при полном разрешении это недостижимо (только `color` на большой кисти = потолок ~14 fps). Понижение разрешения жертвует качеством. Правильное решение — перенести попиксельную работу на параллельное железо (GPU).

## Решения (из брейншторма)

1. **Точность:** визуальная эквивалентность + улучшения приветствуются (не пиксель-в-пиксель). Карта эстетическая, не расчётно-критичная.
2. **Границы:** GPU-нативные органичные границы через **domain warp** (искажение координаты шумом) вместо CPU-сглаживания Чайкина. Другой стиль (извилистый «от руки»), обычно красивее для фэнтези, и **бесплатный** — что делает редактирование бесплатным при любом размере кисти.
3. **Механизм:** **fragment-шейдер на материале карты** (карта живёт как шейдер, перерисовывается каждый кадр сама), а не compute-в-RenderTexture. Бонус: карта становится **разрешение-независимой** (резкая на любом зуме, без фиксированной 2048² и её замыливания).
4. **Совместимость:** данные для шейдера — **через текстуры, без `StructuredBuffer`** (работает на любом железе; Built-in RP, Shader Model 3-совместимо).

## Архитектура

Карта = квадр с кастомным unlit fragment-шейдером. Два входа с GPU + uniform'ы:

1. **Cell-id текстура** (`RFloat`, 2048²) — «какой пиксель какой клетке принадлежит». Печётся на CPU **один раз** при генерации/загрузке (nearest-cell растр — уже вычисляется в текущем `buffers.CellId`). При правке кистью **не меняется** (сайты Вороного не двигаются — установлено фиксом A этой сессии), поэтому грузится на GPU однократно. Point-фильтр.
2. **Текстура атрибутов** (`RGBAFloat`, ~2 тексела на клетку, ~40 КБ) — индекс = `cellId`. На клетку: семейство биома, высота, температура, тип (суша/океан/озеро), `regionId`. Полосу высоты шейдер считает сам из высоты + uniform (число полос). Point-фильтр.
3. **Coast-distance текстура** (`RFloat`, 2048²) — поле дистанции до берега для широкого свечения. Пересчитывается **только при смене топологии суша/вода** (см. ниже), не на каждый мазок.
4. **Uniform'ы:** тема палитры (или таблица палитры как маленькая текстура/массив), режим отображения, показ слоёв биом/рельеф, darkness, параметры domain-warp (amount/scale), сила рельефа/азимут света, число полос высоты, ширина свечения и т.п.

### Шейдер (на каждый пиксель/фрагмент)
1. **Domain warp:** `uv2 = uv + warpAmount * fbm(uv * warpScale)` (две выборки fbm на x/y-сдвиг).
2. Читает **cell-id** по `uv2` (point) → читает **атрибуты** этой клетки.
3. Считает цвет по режиму:
   - **Высота** — градиент по высоте;
   - **Регион** — цвет-хэш по `regionId`;
   - **Биом** — плоский цвет семейства;
   - **Комбинированный** (по умолчанию) — полный конвейер: цвет семейства → ступень высоты → **рельефное затенение** (градиент высоты соседей → hillshade + холодный лунный подсвет) → региональная тонировка по температуре → зерно (value-шум) → **тёмная обводка берега** (детект смены cell-id у соседей) → **свечение берега** (по coast-distance текстуре, сторона воды) → виньетка.
4. Формулы `HillshadeBrightness` и `Noise` портируются из C# в HLSL (простые: dot-product + value-шум).

### CPU-сторона (дёшево)
- **Генерация** — без изменений (производит клетки).
- **Разовая запечка cell-id текстуры** — nearest-cell растр по `NearestCellLookup` (разбиваемо на чанки для прогресс-бара). Единственный тяжёлый CPU-проход, но одноразовый.
- **Построение/обновление текстуры атрибутов** — из данных клеток; при правке обновляются изменённые клетки и текстура перезаливается целиком (~40 КБ → <0.1 мс).
- **Хит-тест** (кисть/POI) — через `NearestCellLookup.FindNearest` (пиксельный cell-id буфер для этого больше не нужен).
- **Coast-distance** — пересчитывается порейонно на CPU (переиспользуем существующий `ComputeCoastDistanceRect`) только когда мазок изменил статус суша/вода хотя бы одной клетки.

## Поток правки (почему бесплатно)
1. Кисть меняет данные клеток на CPU — как сейчас (`BrushOps`/`CellOverrideService`, без изменений).
2. Обновляем CPU-зеркало атрибутов для изменённых клеток; перезаливаем текстуру атрибутов (<0.1 мс).
3. Если изменился статус суша/вода — ставим флаг «топология грязная», пересчитываем coast-distance (~20–40 мс, порейонно) и заливаем.
4. GPU перерисовывает карту в следующем кадре.

Итог: «перезапекание» из ~160 мс → **<1 мс** для обычной покраски (вглубь суши/воды, смена биома/высоты без пересечения уровня моря). Правка **прямо по береговой линии** — с лёгкой заминкой на пересчёт поля дистанции (меньшинство правок). Оба случая независимы от размера кисти.

## Что переиспользуем / заменяем
- **Переиспользуем:** значения палитр (`MapPalette`), `NearestCellLookup`, классификацию биом→семейство (`MapPalette.GetFamily`), формулы `RegionColorPalette.HillshadeBrightness` и `Noise` (портируем в HLSL), `ComputeCoastDistanceRect`.
- **Заменяется шейдером (в активном рендере):** попиксельный painted-конвейер `MapRasterizer` (`BakePaintedPixel`/`ColorForLandPixelFlat`/цвет/виньетка), CPU-трассировка/растеризация границ (`CoastlineContour` для живого рендера), per-stamp путь `RebakeRegion`.
- **CPU-путь сохраняем за флагом как фолбэк** на время миграции (страховка на случай несовместимой GPU / будущий экспорт карты в PNG); убираем, когда GPU докажет надёжность. Фиксы A+B этой сессии остаются полезны для запечки cell-id и как фолбэк — коммитим их (с удалением инструментации) до старта GPU-работы.

## Совместимость с существующими системами
- **Сохранение/загрузка** (`.dndproj`): пишут/читают данные клеток (без изменений). На загрузке — заново печём cell-id + строим атрибуты + coast-distance.
- **POI / заметки:** отдельные системы, не затрагиваются.
- **Undo мазков:** восстанавливает данные клеток → обновляем атрибуты (+ coast-distance при смене топологии). Дешевле нынешнего.
- **Экран генерации** («Отрисовка карты»): запечка cell-id (разбиваемо для прогресса) + атрибуты + coast-distance. Тяжёлый попиксельный цвет ушёл на GPU.
- **Режимы/слои:** становятся uniform'ами — переключение мгновенное и бесплатное (сейчас — полный перезапек).

## Границы задачи (scope)
Только переархитектура **подпроекта 1 (растровая заливка террейна) на GPU**. НЕ входят и идут после: спрайты рельефа (гор/деревьев), реки, редизайн POI-медальонов, подписи/рамка/компас, UI настроек палитры.

## Технический стек
Unity 2022.3 LTS, Built-in Render Pipeline. Кастомный unlit fragment-шейдер (ShaderLab + HLSL). Две-три текстуры (cell-id `RFloat`, атрибуты `RGBAFloat`, coast-distance `RFloat`), point-фильтр. **Новых пакетов нет** (без Burst, без compute-шейдеров — только fragment-шейдер + текстуры).

## Фазирование (детали — в плане реализации)
0. Забанить фиксы A+B (убрать инструментацию, коммит), обновить ledger.
1. Инфраструктура: cell-id текстура + текстура атрибутов + минимальный шейдер (плоский цвет семейства) на квадре; убедиться, что карта отображается.
2. Полный набор эффектов в шейдере до визуальной эквивалентности (рельеф, тонировка, зерно, виньетка, вода, свечение, organic-границы). Интерактивная настройка по скриншотам.
3. Правка кистью / undo / save-load обновляют текстуру атрибутов; хит-тест через `NearestCellLookup`.
4. Coast-distance по смене топологии (CPU-версия).
5. Вывод CPU-пути из активного рендера (оставить за флагом-фолбэком).

## Риски и открытые вопросы
- **Точный вид границ/эффектов** будет отличаться от нынешнего CPU — это принято (эквивалентность + улучшения). Настройка warp/шума — интерактивно по скриншотам (стиль работы пользователя).
- **Разрешение cell-id (2048²)** ограничивает резкость границ клеток на экстремальном зуме (сам цвет разрешение-независим). На обычном зуме незаметно; domain-warp это маскирует. При необходимости позже — cell-id в более высоком разрешении или nearest-in-shader.
- **Свечение берега при правке по берегу** — не бесплатно (CPU-пересчёт поля дистанции). Если понадобится шёлковым — позже перенести поле дистанции на GPU (jump-flood, ~2–5 мс).
- **Портирование формул в HLSL** (`Noise`/`HillshadeBrightness`) — риск мелких расхождений; допустимо в рамках «эквивалентности».
- **Точность `RGBAFloat`/`RFloat` текстур** на целевом железе — стандартные форматы, поддерживаются повсеместно на Windows.

## Критерии успеха
- Редактирование кистью — **константа <1 мс** (обычная покраска), fps упирается в монитор при любом размере кисти. Цель ≥25–30 fps достигается с большим запасом.
- Визуально — эквивалентно или лучше нынешнего (тёмное фэнтези, сглаженные/органичные границы, рельеф, свечение).
- Сохранение/загрузка, POI, undo, хит-тест, режимы отображения — работают как раньше.
- Смена режима/слоя — мгновенная.
