# Дизайн: декорации карты — iso-спрайты террейна (sub-project C, часть 1)

Дата: 2026-07-09
Статус: утверждён в брейншторме, готов к плану
Эталон: `design_handoff_realmweaver_map/` (Terra Umbrarum), раздел «Sprites (side-view "iso" elements)»

## Контекст

Карта уже рендерится как один плоский квад в плоскости XZ с фрагмент-шейдером
(`MapTerrain.shader`, sub-projects A+B, слито и выпущено в v0.2.0). Камера —
**ортографическая, строго сверху вниз** (`Euler(90,0,0)`), мир `[0..mapWidth] × [0..mapHeight]`.

Эта спека добавляет **первый декоративный слой**: side-view «фейк-изометрия» спрайты
террейна поверх карты — горы, деревья (хвоя/осень), меса, холмы. Это придаёт карте
«рукотворную фэнтези» подачу поверх уже существующей заливки биомов.

Sub-project C в целом больше (медальоны POI, region-лейблы, хром, fog of war) — здесь
**только iso-спрайты террейна**; остальное — отдельные спеки позже.

## Ключевые решения (из брейншторма)

1. **Точность:** «тот же стиль, прагматично» — явно те же side-view элементы (освещённая
   грань + снег + перекрытие), **без** тонкой штриховки скал, пер-сегментного света и
   атмосферной дымки. Иконки на мокапе — пример, не пиксель-в-пиксель цель.
2. **Заменяемость арта:** конкретные картинки спрайтов — **сменяемый контент**. Движок
   расстановки/рендера стабилен; арт подложить позже без изменения движка. (Зеркалит
   существующий паттерн POI: процедурный `PoiPlaceholderFactory` сейчас + путь замены.)
3. **Правка кистью:** декорации обновляются на **отпускании кисти** (`EndBrushStroke`),
   инкрементально в затронутой области — по образцу label-текстуры (`FinalizeLabels`).
   Во время штриха не трогаются.
4. **Рендер:** **GPU-инстансинг сразу** (`Graphics.RenderMeshInstanced`), не пул
   SpriteRenderer'ов. В духе проекта (весь рендер уже на GPU ради слабого железа).
5. **Некликабельно:** декорации не имеют коллайдеров, не воруют ввод у кисти/POI/выбора.

## Архитектура

Namespace `WorldGen.Rendering.Decorations`. Три части с чётким швом «расстановка → рендер»,
плюс интеграция в `WorldMapRenderer`.

### Данные
- `DecorationInstance` (struct): `Vector2 worldPos` (XZ), `int typeId`, `int styleCategory`,
  `int artVariant`, `float scale`, `Color32 tint`, `float sortZ`. Плоский «что и где рисовать».
- `enum DecorationType { Mountain, Pine, AutumnTree, Mesa, Hill }` (data-driven — добавить
  тип = правило + слоты атласа). `Reeds` **отложен** (нет семейства Marsh, см. ниже).

### Двухуровневая модель вариантов (контекст + арт)
Каждый инстанс выбирает **две** оси:
- **`styleCategory`** — контекст-категория, **детерминирована по биому/температуре клетки**
  (не случайна). Напр. у гор: `Snowy` (заснеженные вершины) / `Forested` (склоны в лесу) /
  `Bare` (голые скалы). Это ответ на «гора должна зависеть от того, где стоит».
- **`artVariant`** — конкретная картинка внутри категории, **выбирается по hash** (форма
  силуэта, зеркалирование). Даёт разнообразие в пределах одной категории.

Каталог/атлас ключуется `(type, styleCategory, artVariant)`. Категории по типам заданы
data-driven, так что «похожие вариации для других регионов» добавляются тем же механизмом.

### 1. `DecorationPlacer` — чистый C#, без Unity-рендера (юнит-тестируемый)
- Вход: `IReadOnlyList<VoronoiCell>`, `NearestCellLookup`, `int seed`, размер карты,
  `DecorationConfig` (плотность/пороги/масштаб по типам).
- Выход: `List<DecorationInstance>`. Детерминирован.
- Умеет полный проход **и** прямоугольник (для правок на отпускании кисти).

### 2. `DecorationCatalog` + `DecorationAtlasBaker` — сменяемый источник арта
- Строит **один RGBA32-атлас** (цветной, sRGB — не data-текстура); отдаёт UV-rect на
  `(тип, styleCategory, artVariant)` + число artVariant'ов на `(тип, styleCategory)`.
- v1: `DecorationPlaceholderFactory` процедурно рисует спрайты в слоты (зеркало
  `PoiPlaceholderFactory`), 2–3 artVariant'а на категорию (напр. гора Snowy/Forested/Bare ×
  несколько силуэтов).
- Шов замены: тот же baker может запаковать будущие `Sprite`/`Texture2D`-ассеты; `Placer`
  и `Renderer` не меняются (видят только UV-rect'ы + число вариантов).

### 3. `DecorationRenderer` (MonoBehaviour, child `mapRenderer.transform`) + `Decorations.shader`
- Держит массив инстансов; сортирует по `sortZ` (back-to-front); сабмитит
  `Graphics.RenderMeshInstanced` каждый кадр батчами ≤1023 в отсортированном порядке.
- Без коллайдеров → некликабельно. Тумблер слоя и общий масштаб — флаг/юниформ.

### Поток данных
`generate / load / EndBrushStroke` → `DecorationPlacer` (список инстансов) →
`DecorationRenderer` (сортировка + инстанс-сабмит каждый кадр, семплит `DecorationCatalog`-атлас).
Список инстансов **renderer-agnostic** — рендерер можно позже заменить (напр. RenderMeshIndirect)
без изменения движка расстановки и каталога.

## Правила расстановки (Секция B)

**Независимые проходы по типам** (как в хэндоффе: у гор своя редкая сетка, у деревьев частая).
Для каждого типа — свой джиттер-грид со своим шагом; в каждой грид-точке проверяется предикат
типа + вероятность(hash) → ставим/пропускаем. Типы **накладываются** (деревья на подножьях гор).

Словарь биомов проекта (проверено в `MapPalette.cs`):
`BiomeFamily { Sea, Lake, Coast, Snow, Tundra, Highland, Badlands, Forest, ForestWarm, Moor, Plains }`,
`MapPalette.GetFamily(Biome)` даёт семейство; высота — `cell.EffectiveElevation` [0..1];
суша — `RegionCategories.IsLandCell(cell)` = `!(EffectiveIsOcean || EffectiveIsLake)`.

| Тип | Предикат размещения (в точке сэмпла, только суша) | Драйвер | `styleCategory` (по контексту клетки) |
|---|---|---|---|
| **Mountain** | `EffectiveElevation ≥ mtnHi` (дефолт ~0.72) | высота | `Snowy` если `EffectiveTemperature < coldT` или семейство ∈ {Snow, Tundra}; иначе `Forested` если семейство ∈ {Forest, ForestWarm}; иначе `Bare` |
| **Hill** | `hillLo ≤ elev < mtnHi` (дефолт ~0.55) | высота | `Snowy` / `Forested` / `Bare` по той же логике (редкие бугры под горами) |
| **Pine** | семейство `Forest` (Taiga / TemperateRain / TemperateDeciduous) | биом | `Snowy` (снег-припорошка) если холодно, иначе `Plain` |
| **AutumnTree** | семейство `ForestWarm` (TropicalRain / TropicalSeasonal) | биом | `Plain` (v1 одна категория; расширяемо) |
| **Mesa** | семейство `Badlands` (Scorched / TemperateDesert / SubtropicalDesert) | биом | `Plain` (v1 одна категория; расширяемо) |
| ~~Reeds~~ | семейства Marsh **нет** → отложено | — | — |

**`styleCategory` детерминирована** (по биому/температуре клетки под сэмплом), **`artVariant`
случаен** (hash). Категории задаются в конфиге per-type — «похожие вариации для других
регионов» (напр. осенний лес → сухой/яркий, меса → высокая/низкая) добавляются позже тем же
механизмом, без изменения движка. v1 несёт минимум категорий: у гор/холмов три (Snowy/Forested/Bare),
у хвои две (Snowy/Plain), у остальных одна.

Пороги высоты/плотности — **сериализованные поля + слайдеры** (как пляж), не хардкод:
распределение `EffectiveElevation` зависит от генерации.

**Детерминизм:** `hash(gridX, gridY, seed, typeSalt)` управляет: ставить/пропустить (порог
вероятности), джиттер позиции внутри грид-ячейки, `artVariant`, джиттер масштаба,
зеркалирование по X. `styleCategory` берётся из биома/температуры клетки под сэмплом (не из
hash). Один сид + одни клетки → одна расстановка.

**Тон:** из активной темы (`mapRenderer.paletteTheme` + `MapPalette.GetSlotColor`), с учётом
`styleCategory`: голые горы — `MtnL/MtnS`, снежные — `Snow` поверх, лесистые — подмешать
`Forest`; хвоя — `Forest`, осень — `ForestWarm`, меса — `Badlands`, холмы — по своей категории;
плюс лёгкий per-instance джиттер яркости.

**Живой апдейт (rect-scoped):** на `EndBrushStroke` для затронутого мирового прямоугольника —
выкинуть инстансы, чьи грид-точки попали в rect, заново прогнать сетки всех типов по rect,
вмёржить, ре-сортировать. Т.к. расстановка детерминирована по грид-точке, пересчёт rect даёт
ровно то же, что дал бы полный прогон там → без швов.

**Сортировка:** `sortZ = worldPos.z` — ближние (по экрану нижние) спрайты перекрывают дальние.
Знак/направление подтверждается при реализации по ориентации камеры (`Euler(90,0,0)`,
screen-Y ↔ world-Z инвертирован, см. `MapCameraController.HandleRightMouseDragPan`).

## Рендер (Секция C)

- **Квад-меш** в плоскости XZ, пивот в **низу-центре** — спрайт «вырастает» из точки земли
  (`worldPos` = основание, арт уходит в экранный «верх»).
- **`Decorations.shader`**: unlit, alpha-blend, `#pragma multi_compile_instancing`. Семплит
  атлас по per-instance UV-rect `(тип, styleCategory, artVariant)`, умножает на per-instance
  tint, плоско в XZ. Transparent-очередь чуть **ниже POI** (POI остаются сверху), `ZWrite Off`,
  `Cull Off`.
- Сабмит `Graphics.RenderMeshInstanced` (Unity 6) каждый кадр из `DecorationRenderer`, батчами
  ≤1023 (лимит инстанс-массива), в порядке back-to-front. Per-instance: TRS-матрица
  (позиция = `worldPos` + Y-лифт слоя; масштаб = `scale * decorationScale`) + кастом-данные
  (UV-rect атласа `float4`, tint `Color`). `RenderParams` с инстанс-материалом, границами
  (bounds карты), без теней/лайт-проб.
- **Слой Y:** единый Y-лифт для всего слоя, между границами (0.4) и POI (0.5) — напр. ~0.45.
  Перекрытие внутри слоя решается порядком отрисовки (back-to-front sort), не Y.
- **Кап** общего числа инстансов (`maxInstances`, дефолт напр. 6000): при превышении
  троттлим плотность и пишем `Debug.Log` (без «тихих» лимитов).
- Immediate-mode (сабмит каждый кадр) → живые правки = мутация CPU-массива, следующий кадр
  показывает. Никаких GameObject'ов на инстанс, нет per-instance churn.

## Конфиг / UI

- `DecorationConfig` — `[System.Serializable]` класс с полями: мастер-вкл; per-type
  плотность/вероятность + шаг грида; пороги `mtnHi`/`hillLo`/`coldT`; общий `decorationScale`;
  `maxInstances`. Один экземпляр — сериализованное поле на `WorldMapRenderer` (правится в
  Inspector, живой `OnValidate` как beach-слайдеры); тот же объект передаётся в
  `DecorationPlacer` как вход (не дублируем параметры).
- Тумблер **«Декорации»** в `MapLayersPanel` → включает/выключает сабмит рендерера.
- Отдельная панель не нужна для v1 (слайдеры в Inspector, консистентно с beach/roundness).

## Интеграция в `WorldMapRenderer`

- После `RebakeAll` / `RebakeAllStepped` (генерация/загрузка) — построить полную расстановку
  (`DecorationPlacer` над `Cells` + `nearestLookup` + `seed`) и отдать `DecorationRenderer`.
- На `EndBrushStroke` (и `RefreshAfterCellDataChange` для undo/bulk-override) — rect-scoped
  пересчёт затронутой области.
- Тумблер слоя из `MapLayersPanel`.
- Смена темы карты (сейчас рантайм-свитчера нет) — при добавлении пересчитать тона; сегодня
  тон берётся один раз при построении из `paletteTheme`.

## Персистентность

Декорации **производны** от `Cells` + `seed` → **не сохраняются** в `.dndproj`, пересчитываются
на загрузке (как весь рендер карты). Старые сейвы грузятся без изменений (модель данных клеток
не трогается). Нечего мигрировать.

## Тестирование

Агенты не запускают Unity → self-tests это `[ContextMenu]`, гоняет юзер; ревью статические.

- `DecorationPlacer` (чистый C#):
  - **детерминизм** — один сид → идентичный список;
  - **предикаты** — Mountain только на клетках `elev ≥ mtnHi`, Pine только на семействе Forest,
    Mesa только на Badlands, вода/озеро всегда пусто;
  - **styleCategory** — снежная гора только при холоде, лесистая только над Forest/ForestWarm,
    иначе Bare (детерминировано по контексту клетки, не по hash);
  - **rect == full** — под-прямоугольник полного прогона идентичен rect-scoped пересчёту;
  - **масштаб плотности** — рост плотности увеличивает число инстансов монотонно;
  - **кап** — при превышении `maxInstances` результат обрезан и залогирован.
- Атлас/каталог: UV-rect'ы всех `(тип, styleCategory, artVariant)` в границах [0..1]; число
  artVariant'ов на каждую `(тип, styleCategory)` > 0.
- Рендер: визуальная проверка юзером в Editor (инстансинг/сортировка/тон/тумблер слоя);
  агенты не могут прогнать GPU.

## Риски / открытые вопросы

- **Порядок отрисовки между слоями:** декорации (RenderMeshInstanced, transparent) vs POI
  (SpriteRenderer, transparent). Обеспечить, что POI поверх — очередью материала ниже
  `Sprites/Default` (3000) и/или порядком. Проверить визуально.
- **Знак `sortZ`:** направление «ближе/дальше» подтвердить по камере в play mode.
- **Инстанс-данные на GLES/слабом железе:** `RenderMeshInstanced` с CPU-массивами (не
  StructuredBuffer/compute) — совместимо с GLES3.0+. Избегать `RenderMeshIndirect` (SM4.5).
- **Плотность vs производительность:** кап + слайдеры; замерить на большой карте.
- **Tint-дружественность плейсхолдеров:** рисовать так, чтобы все 4 темы читались (люминанс +
  tint), иначе финальный арт сам несёт цвет.
- **Стрипинг шейдера из билда (КРИТИЧНО, уже кусало):** `Decorations.shader` грузится в рантайме
  через `Shader.Find` (материал не сериализован) → Unity вырезает его из билда → `Shader.Find`
  вернёт `null` → краш. **Обязательно добавить `WorldGen/Decorations` в Project Settings →
  Graphics → Always Included Shaders** (как `WorldGen/MapTerrain` после фикса v0.2.0, где именно
  это уронило генерацию на 67%). Плюс defensive null-check в создании материала с понятным
  `Debug.LogError`, чтобы падать громко, а не «зависать».
