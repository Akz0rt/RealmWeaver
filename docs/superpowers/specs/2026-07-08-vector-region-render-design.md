# Векторный рендер регионов (чёткие сглаженные контуры) — Design Spec

**Дата:** 2026-07-08
**Ветка:** `map-terrain-raster`
**Место в дорожной карте:** Подпроект **B (векторный рендер)** из декомпозиции «тёмный фэнтези-рендер карты»
(A генерация → **B векторный рендер** → C декорации). A завершён. Этот spec покрывает только B.

## Контекст и цель

Текущий GPU-рендер (`MapTerrain.shader` + cell-id/attribute/coast-distance текстуры) уже даёт плоскую заливку по
биому, пояса высот, hillshade + холодный подсвет, температурный тон, зерно, виньетку, глубину воды и широкое
свечение берега. Единственный «размытый» элемент — **domain-warp**, искажающий координату перед lookup'ом клетки:
границы «гуляют», они не чёткие и не гладкие кривые. Отдельных линий границ биомов в шейдере нет.

Цель B — заменить «гуляющий» warp на **чёткие сглаженные векторные контуры**, трассированные из вершин полигонов
Вороного и сгруппированные по **семейству биома + поясу высоты**, залить получившиеся области плоско, оставить
рельеф/свечение/палитру, добавить тонкую линию-обводку между семействами биомов и мягкий переход песок→биом у
берега. Результат — «нарисованная» карта в духе макета `design_handoff_realmweaver_map` (Terra Umbrarum), без
пушистых пятен.

**Ключевая уже готовая машинерия (переиспользуется):** `MapRaster/CoastlineContour.cs` —
`TraceSmoothedLoops(corners, cellById, Func<VoronoiCell,bool> inRegion, smoothingIterations, decimationDistance)`
трассирует сглаженные (Chaikin) граничные петли из corner-вершин для ЛЮБОГО предиката региона и возвращает
`List<List<Vector2>>`; `RasterizeRegionLabel(...)` заливает петли в целочисленный label-буфер even-odd-сканлайном
(rect-scoped); `EdgesOverlappingY(...)` — Y-culling рёбер для скорости. Всё уже написано, компилируется, покрыто
self-тестами; сейчас живёт в CPU-fallback пути (`useGpuRenderer=false`). B поднимает эту трассировку в активный
GPU-путь: **CPU трассирует+растеризует label'ы, GPU красит.**

## Подтверждённые решения (из брейншторма)

1. **Техника — label-текстура** (не меши): границы печём в текстуру высокого разрешения. Чётко на нормальном
   зуме, чуть мягчает при сильном приближении (как сейчас клетки). Переиспользует текущую GPU-архитектуру, риск
   низкий. (Отвергнут mesh-подход: вектор на любом зуме, но триангуляция вложенных регионов сложна.)
2. **Группировка** — семейство биома + пояс высоты (обе категории — сглаженные области).
3. **Контуры** — Chaikin-сглаженные, трассированные из вершин полигонов (не по попиксельному шуму).
4. **Линии-обводки — только между семействами биомов** (крупные регионы). Между поясами высот линий НЕТ (пояс —
   просто ступень оттенка). Береговая тёмная обводка остаётся.
5. **Пляж** — мягкий переход песок→биом у берега (по coast-distance), НЕ жёсткая линия.
6. **Рельеф/свечение/палитра** — оставляем как есть; «холоднее/единее/спокойнее» — интерактивный тюнинг
   слайдерами в Editor, не переписывание.
7. **Поведение кисти** — во время мазка мгновенная угловатая заливка по клеткам (бесплатно), гладкие контуры
   **оседают при отпускании** кнопки.

## Архитектура

### Слой данных (текстуры)

Оставляем 3 текущие текстуры:
- **cell-id** (RFloat, ~2048 по длинной стороне): ближайшая клетка на пиксель. Печётся один раз при
  генерации/загрузке, при правке не меняется (сайты Вороного неподвижны). Нужна B для сэмплинга соседних высот
  (рельеф) и статуса воды.
- **attribute** (RGBAFloat, ~2 тексела/клетку): (family, elevation, temperature, waterType) на клетку.
  Дешёвая правка при редактировании.
- **coast-distance** (RFloat, 1/4-разрешения): дистанция до суши. Пере-строится один раз при отпускании кисти.

Добавляем **label-текстуру сглаженных областей** — одна `RG8` (или `RGBA8`) текстура растрового разрешения:
- канал **R** = `familyLabel` (индекс семейства биома, ≤11 значений → байт),
- канал **G** = `bandLabel` (индекс пояса высоты, ≤8 → байт).
Байтовых каналов достаточно; одна текстура ~4–8 МБ при 2048². (Опционально доп. канал под «граница/берег»-маску,
если понадобится в шейдере — решается в плане.)

### CPU-выпечка контуров (переиспользуем `CoastlineContour`)

- **При генерации/загрузке (полная выпечка):** для каждого семейства биома и каждого пояса высоты трассируем
  сглаженные петли (`TraceSmoothedLoops` с предикатом `FamilyOf(cell)==f` / `BandOf(cell)==b`) в порядке
  приоритета, растеризуем в `familyLabel`/`bandLabel` (`RasterizeRegionLabel`), грузим в `RG8`-текстуру.
  Разрешение растеризации label'ов — растровое (как cell-id) или чуть ниже (границы гладкие, терпят). Выпечка
  **чанками** (корутина, как существующий `RebakeAllStepped`) → без фризов на экране прогресса генерации.
- **При правке кистью:**
  - *Во время мазка (per stamp):* только дешёвый per-cell патч (как сегодня) → мгновенная **угловатая** заливка
    затронутых клеток. Гладкие контуры НЕ пересчитываются на каждый штамп.
  - *При отпускании (per stroke, mouse-up):* пере-трассируем ТОЛЬКО категории, чьи клетки реально изменились, и
    пере-растеризуем **rect-scoped** затронутую область (с `EdgesOverlappingY`). Один разовый ~десятки мс на
    штрих, не на кадр. Coast-distance пере-строится там же (как сегодня).

### Шейдер (переписываем fill/border-часть `MapTerrain.shader`)

- **Убираем `warpUV`/domain-warp** — источник размытости. Lookup идёт по прямой UV.
- **Заливка суши** = `palette[familyLabel]`, модулированная поясом высоты из `bandLabel` (дискретные ступени
  контраста, как сейчас `_ElevBands`/`_BandContrast`, но по СГЛАЖЕННОМУ `bandLabel`, а не по попиксельной высоте).
- **Линия-обводка между семействами биомов:** тонкий тёмный штрих там, где `familyLabel` отличается у соседа
  (4-tap тест, как нынешняя береговая обводка). **НЕ** рисуется между поясами высот и **НЕ** на границе
  берег/суша (там — мягкий переход пляжа, см. ниже).
- **Оставляем без изменений:** hillshade + холодный подсвет (из cell-id+attribute по высоте), температурный тон,
  зерно, виньетка, глубина воды, широкое свечение берега.
- **Пляж (мягкий песок→биом):** у берега подмешиваем песочный тон в биом по `coast-distance` (сила песка спадает
  вглубь суши на «ширину пляжа»); переход плавный, без линии. Взаимодействие с классификацией Beach из A —
  **открытый пункт** (см. Риски): A пометил прибрежные клетки биомом Beach (familyLabel=Coast); нужно решить,
  рисует ли B песок из coast-distance поверх подлежащего биома или из самой Coast-области — уточняется в плане.

### Поведение редактирования (сводка)

Мгновенная угловатая обратная связь во время мазка (per-cell) → гладкие контуры оседают при отпускании
(пере-выпечка label'ов затронутой области). Пользователь всегда видит немедленный отклик заливки; «векторность»
границ появляется на mouse-up.

## Производительность и распределение нагрузки GPU/CPU (первоклассное требование)

Явный приоритет пользователя: приложение должно работать быстро и без сбоев за счёт оптимального распределения
CPU/GPU.

- **GPU (каждый кадр, каждый пиксель):** ВСЯ заливка/рельеф/линии-границы/тон/зерно/виньетка/вода/свечение/пляж —
  в шейдере. Стоимость масштабируется размером экрана, а не размером карты; зум/пан — бесплатны.
- **CPU (редко, вне hot-path):**
  - генерация/загрузка: трассировка контуров (O(corners), дёшево) + растеризация label'ов (O(пикселей),
    **чанками через корутину** → без фриза);
  - отпускание кисти (mouse-up): пере-трассировка только изменившихся категорий + **rect-scoped** растеризация
    (Y-culled рёбра) — разово ~десятки мс на штрих;
  - во время мазка (per stamp): только дешёвый per-cell патч — мгновенно;
  - cell-id текстура: печётся один раз, при правке не трогается;
  - coast-distance: пере-строится один раз на штрих.
- **Инварианты:** никакой CPU-работы per-frame; никакой трассировки per-stamp; тяжёлые выпечки — только чанками.
  Это удерживает 30+ fps при редактировании (то, ради чего изначально ушли на GPU) и исключает фризы.
- Бюджет памяти: +1 label-текстура (~4–8 МБ при 2048²). Приемлемо.

## Переиспользование существующего кода

- `MapRaster/CoastlineContour.cs` — трассировка/сглаживание/растеризация label'ов (готово, покрыто self-тестами).
- `MapRaster/MapRasterizer.cs` — логика `FamilyCategoryOf`/`BandCategoryOf`/`FamilyPriority`/`RasterizeSmoothedCategoryRect`
  (старый CPU flat-fill путь) как эталон категоризации/приоритетов; B поднимает её в GPU-путь.
- `GpuMap/` — инфраструктура GPU-текстур (`CellAttributeTexture` как образец per-cell текстуры; добавляем
  аналогичный `RegionLabelTexture`).
- `MapPalette` — цвета семейств/поясов.

## Взаимодействие с существующим кодом

- **Убирается:** `warpUV`/domain-warp из шейдера + связанные uniform'ы (`_WarpAmount`/`_WarpScale`, если больше
  нигде не нужны).
- **Остаётся:** cell-id/attribute/coast-distance текстуры и их шейдерные ветки (рельеф/вода/свечение).
- **`MapBorderBuilder`** (меш-оверлей границ, сейчас выключен) — B рисует границы биомов в шейдере, так что
  меш-оверлей регионов остаётся выключенным; не удаляем (может пригодиться под политические границы регионов в C).
- **CPU-путь `MapRasterizer`** (`useGpuRenderer=false`) — B не трогает его; его удаление — отдельный отложенный
  план remove-CPU (после B).
- **Live-edit Beach** (`CellOverrideService` всё ещё по высоте) — render рисует песок по coast-distance, который
  пере-строится на mouse-up, поэтому берег корректно отражает и правки воды кистью **без** зависимости от
  Beach-классификации в override-системе (обходит открытый в A вопрос).

## Риски и открытые вопросы

- **Скорость пере-выпечки на mouse-up.** Должна остаться ~десятки мс: пере-трассировать только изменившиеся
  категории (не все), rect-scoped растеризация, `EdgesOverlappingY`. Если штрих большой/на плотной карте — измерить
  и, при нужде, инкрементально кэшировать петли неизменившихся категорий (как отмечалось в старых заметках).
- **Механика «угловато во время мазка → гладко при отпускании».** Нужно, чтобы во время мазка label-текстура
  показывала угловатую (по клеткам) заливку затронутых клеток, а на mouse-up — сглаженную. Механизм (патч
  faceted-label per stamp vs шейдерный fallback на cell-id для «грязных» клеток) — уточняется в плане.
- **Пляж vs A-Beach-классификация** (см. Шейдер·Пляж): песок из coast-distance поверх биома, или из Coast-области;
  и не рисовать линию-границу на берегу. Финализируется в плане (влияет на то, надо ли B знать про familyLabel=Coast
  особым образом).
- **Композиция линия+пляж+свечение** у берега не должна конфликтовать (линия — только меж-биомная, не береговая).
- **Разрешение label-текстуры** vs чёткость на зуме — 2048 как cell-id даёт паритет с текущим; выше — чётче, но
  дороже по выпечке/памяти. Стартуем с растрового, тюним.

## Вне объёма (следующее)

- **C (декорации):** иконки биома/рельефа, подписи регионов, рамка/компас/масштаб.
- Редизайн палитры (оставляем текущую + тюнинг).
- Удаление CPU-рендер-пути (`MapRasterizer`/`useGpuRenderer`) — отдельный отложенный план после B.
- Политические границы регионов (RegionId) как отдельный слой — потенциально C, через `MapBorderBuilder`.
