# Тёмный фэнтези-рендер карты — Плоская заливка по регионам + полосы высоты

## Контекст

В painted-режиме (Combined+smoothBorders) каждый сухопутный пиксель сейчас получает цвет через взвешенный по расстоянию (1/(d²+ε)) блендинг цвета биом-семейства среди соседних клеток в радиусе `smoothRadius` (`MapRasterizer.BakePaintedFields`), а поверх — тонировку по непрерывной температуре, региональный шум, hillshade, зерно и лайтнесс-вариацию (`ColorForLandPixel`). Результат: «мыльные» переходы между биомами, а абсолютная высота («что выше, что ниже») не читается — её показывает только hillshade (затенение склонов), который даёт форму, но не абсолютную ступень.

Пользователь хочет **однотонную заливку по зонам с одинаковым биомом и высотой**, чтобы сразу читались биом и высота. Это гипсометрическая заливка: цвет = функция(биом-семейство + дискретная полоса высоты), одинаковый биом+полоса = один ровный тон.

Решения, принятые в брейнсторминге:
- Соседние клетки с одинаковым биомом+полосой сливаются в один тон (внутренних граней Вороного между ними не видно).
- Высота — дискретными полосами (ступени тона), без hillshade. Абсолютная высота читается напрямую.
- Ровный тон + лёгкое зерно (тёмно-фэнтези фактура), но без крупных вариаций.
- Новый тумблер `flatRegionFill` (по умолчанию включён); старый блендинг остаётся доступен.
- Подход A: и биом, и полоса берутся от ближайшей клетки → внутренние границы (биомов и полос) гранёные по Вороному; согласованно и просто. Гладкий берег независим и сохраняется. Сглаживание внутренних границ — возможная отдельная будущая итерация.

## Цели

- Заменить (по тумблеру) блендированную заливку суши на плоскую: цвет = биом-семейство ближайшей клетки, модулированный дискретной полосой высоты.
- Абсолютная высота читается через ступени тона (выше = светлее); число ступеней и контраст — настраиваемые.
- Ровный тон в пределах зоны + лёгкое зерно; без блендинга, hillshade, непрерывной тонировки, крупного шума.
- Тумблер `flatRegionFill` (default on), не ломает существующий блендинг-путь (доступен при выключенном тумблере).
- Побочно: в плоском режиме пропускается дорогой проход блендинга — запек быстрее.

## Не-цели (явно вне этого документа)

- Контраст суши/воды/глубины — отдельная будущая ось; вода в этом документе не меняется (градиент глубины + широкий ореол берега как есть).
- Сглаживание внутренних границ биомов/полос (сейчас гранёные по Вороному) — возможная отдельная итерация, не здесь.
- Гладкий контур берега — уже сделан (спек `2026-07-07-coastline-contour-smoothing-design.md`), не трогаем; плоская заливка использует ту же `IsLand`-маску.
- Прочие режимы (Height/Region/Biome, Combined без smoothBorders) — не трогаются.

## Архитектура

Активно ТОЛЬКО когда `displayMode == Combined && SmoothBorders == true && FlatRegionFill == true`. При `FlatRegionFill == false` painted-путь работает ровно как сейчас (блендинг).

### 1. Пропуск блендинга в `BakeFieldsRect`

В painted-ветке `BakeFieldsRect` сейчас всегда вызывается `BakePaintedFields` (блендинг elevation/temperature/family-color в `buffers.Elevation/Temperature/FamilyColor`). В плоском режиме этот проход **пропускается** — плоская раскраска читает биом и высоту напрямую из ближайшей клетки (`cellById[buffers.CellId[idx]]`), а не из блендированных буферов. `IsLand`-маска (контур берега) и `CoastDistance` (свечение) считаются как обычно — они не зависят от блендинга.

```
if (painted)
{
    ... IsLand (RasterizeIsLand / all-land guard) ...
    if (config.CoastlineGlowWidth > 0) ComputeCoastDistanceRect(...);
    if (!config.FlatRegionFill)
        BakePaintedFields(...);   // блендинг только в НЕ-плоском режиме
}
```

### 2. Развилка в `BakePaintedPixel`

Категория пикселя (суша/вода) по-прежнему из `buffers.IsLand[idx]`. Вода → `ColorForWaterPixel` без изменений (глубина + ореол). Суша:
- `FlatRegionFill == true` → новый `ColorForLandPixelFlat(cell, buffers, idx, x, y, w, h, config, palette, coldAmt)`, где `cell = cellById[buffers.CellId[idx]]` (ближайшая клетка).
- `FlatRegionFill == false` → существующий `ColorForLandPixel` (блендинг, как сейчас).

`BakePaintedPixel` уже имеет `cell` (ближайшую) и передаёт её в `ColorForWaterPixel`; в плоскую сушу передаём ту же `cell`.

### 3. `ColorForLandPixelFlat`

```
static Color32 ColorForLandPixelFlat(VoronoiCell cell, MapRasterBuffers buffers, int idx,
    int x, int y, int w, int h, MapRasterConfig config, ResolvedPalette palette, float coldAmt)
```

Шаги:
1. **Базовый цвет.** `showBiomeLayer` → цвет семейства ближайшей клетки: `MapPalette.GetSlotColor(config.Theme, MapPalette.GetFamily(cell.Biome))`. Иначе нейтральный тан `(209,199,166)` (как в существующем `ColorForLandPixel`).
2. **Полоса высоты (гейт `ShowReliefLayer`).** Если `ShowReliefLayer && ElevationBands > 1`:
   - `band = Mathf.Clamp((int)(cell.EffectiveElevation * ElevationBands), 0, ElevationBands - 1)`
   - `t = ElevationBands > 1 ? band / (float)(ElevationBands - 1) : 0.5f`  (нормированная ступень в [0,1])
   - `factor = 1f + (t - 0.5f) * (ElevationBandContrast / 100f)`  (нижняя полоса темнее, верхняя светлее; при contrast=40 размах ≈ ±20%)
   - `r *= factor; g *= factor; b *= factor;`
   Иначе (рельеф выкл) — базовый цвет без модуляции (чистый биом, один тон).
3. **Береговая обводка** (как в `ColorForLandPixel`): если `HasNeighborWithWaterStatus(buffers, x, y, w, h, wantWater: true)` → жёсткая замена на `palette.Outline` (тёмная тушевая линия со стороны суши, 1px).
4. **Зерно** (как шаг 8 существующего пайплайна): `grain = (Noise.ValueNoise(x*0.5f, y*0.5f, config.Seed+61) - 0.5f) * 7f; r+=grain; g+=grain; b+=grain;`
5. `return ClampColor32(r, g, b);`

**Убрано в плоском режиме** (относительно `ColorForLandPixel`): блендинг (buffers.FamilyColor не читается), непрерывная тонировка по температуре, региональный цветовой шум (шаг 5б), hillshade + холодный подсвет (шаг 6), лайтнесс-вариация (шаг 9). Зерно и береговая обводка сохранены.

Порядок в п.3/п.4: береговая обводка — жёсткая замена (перекрывает базовый цвет полосы), затем зерно применяется поверх (как в существующем `ColorForLandPixel`, где зерно идёт после обводки).

## Кисть и производительность

Плоская раскраска читает только ближайшую клетку (`CellId`-буфер уже заполняется в `BakeFieldsRect` для всего rect) — без `FindWithinRadius`. Пропуск `BakePaintedFields` в плоском режиме убирает основной per-pixel расход, так что и полный запек, и кисть быстрее. Dirty-rect кисти (`ComputeTouchedPixelRect`) не требует изменений: в плоском режиме цвет пикселя зависит только от его ближайшей клетки + маски берега/дистанции, а отступ на `smoothRadius`+`glowWidth` уже с запасом покрывает это (клетка под пикселем и полоса берега). Чанковый `RebakeAllStepped` тоже корректен: плоская раскраска per-pixel не читает соседей (кроме береговой обводки/дистанции, которые считаются в fields-проходе до раскраски).

## Тестирование (самотесты `[ContextMenu]`)

Важно: зерно (шаг 4) — позиционный шум `ValueNoise*7`, то есть даже в идеально плоской зоне два пикселя различаются на ±~7/канал. Поэтому «одинаковый тон» в тестах проверяется с допуском чуть больше амплитуды зерна (напр. > 8/255 при работе в 0..1), а «разный тон» — на разнице, заведомо большей зерна (модуляция полосы/скачок биома дают десятки единиц).

- **Плоскость + слияние зон:** две соседние сухопутные клетки одного биома и одной полосы высоты — цвет в центре клетки и цвет пикселя у их общей границы различаются лишь на величину зерна (малый допуск), т.е. зона ровная без внутреннего градиента. Для контраста: у границы с клеткой ДРУГОГО биома цвет скачком отличается сильно (много больше зерна).
- **Полосы высоты:** одинаковый биом, клетка с высокой EffectiveElevation даёт заметно (много больше зерна) более светлый тон, чем с низкой (при `ShowReliefLayer=true`, `ElevationBands>1`); при `ShowReliefLayer=false` тон обеих клеток совпадает в пределах допуска на зерно (полосы выключены).
- **Тумблер `FlatRegionFill`:** для пикселя ровно у границы двух разных сухопутных биомов результат при `FlatRegionFill=true` (резкий скачок цвета по грани) отличается от `FlatRegionFill=false` (плавный блендинг того же пикселя) — доказывает, что тумблер реально переключает путь.
- **`ElevationBands` квантование:** две клетки одного биома, чьи EffectiveElevation попадают в одну 1/N-полосу, дают тон в пределах допуска на зерно; клетки из соседних полос — заметно разный тон (граница ступени на `k/N`).

## Риски и открытые вопросы

- **Гранёные внутренние границы.** Подход A даёт границы биомов/полос по граням Вороного (не гладкие). Осознанный выбор; если визуально будет мешать — отдельная итерация со сглаживанием (как контур берега). Гладкий берег при этом уже есть.
- **Квантование elevation по [0,1].** Суша занимает под-диапазон (примерно [beachThreshold..1]), поэтому нижние полосы могут быть уже населены. Дефолты (5 полос, contrast 40) подобраны на глаз; финальную калибровку делает визуальная проверка — числа легко поменять полями. Если нижние/верхние полосы окажутся пустыми/переполненными — вариант later перейти на квантование по фактическому диапазону land-elevation (не сейчас, YAGNI).
- **Смысл `ShowReliefLayer` в плоском режиме.** В блендинг-режиме тумблер управляет hillshade; в плоском — показом полос высоты. Разное поведение одного тумблера между режимами — осознанная переинтерпретация («слой рельефа» = информация о высоте в обоих случаях), задокументирована в коде.
